# LendLoop

A small neighbourhood tool library. Neighbours list tools, others request a loan for a date range, the owner approves or
declines, and an n8n automation emails everyone and chases overdue returns.

**Stack:** Next.js (App Router) · Clerk (sign-in) · Convex (database, server functions, HTTP endpoints) · n8n (workflows) · TypeScript.

## What it does

| Area | Behaviour |
|---|---|
| Public page `/` | Shows each tool's **name, category, availability** only. No sign-in needed. |
| Member area `/app` | Browse with category and "available only" filters; list, edit and delete your own tools; request a loan; approve, decline, withdraw and mark returned; each loan shows the latest automation activity. |
| Admin tab | Remove any listing, mark a member **Trusted Lender** (badge shown on their listings), see every loan, see failed or retrying automation runs. |
| Roles | `user` and `admin`, stored in Convex and checked **inside every Convex function**. |
| n8n workflow 1 | Signed webhook from Convex on every loan status change, then an email to the right person. |
| n8n workflow 2 | Daily 09:00 job: fetches overdue loans from Convex, emails each borrower, writes the result back idempotently. |
| n8n workflow 3 | Error workflow: any failed run is reported to Convex and appears in the admin tab. |

## Run it

Prerequisites: Node 22+, Docker, free accounts for [Clerk](https://clerk.com), [Convex](https://convex.dev).

1. `npm install`
2. **Convex:** `npx convex dev` (log in, create a project). It writes `NEXT_PUBLIC_CONVEX_URL` to `.env.local`.
3. **Clerk:** create an application, then in the Clerk dashboard activate the **Convex** integration (this creates the JWT template named `convex`). Copy the publishable and secret keys into `.env.local`, and the instance's issuer URL into Convex:
   `npx convex env set CLERK_JWT_ISSUER_DOMAIN https://<instance>.clerk.accounts.dev`
4. **Shared secret** (used to sign every call between Convex and n8n):
   `SECRET=$(openssl rand -hex 32)`, then `npx convex env set N8N_SHARED_SECRET $SECRET` and put the same value in `.env` for docker-compose.
5. **n8n + a fake inbox:** create `.env` (see `.env.example`), then `docker compose up -d`.
   - n8n: http://localhost:5678, Mailpit inbox: http://localhost:8025.
   - Import and activate the workflows:
     ```
     docker compose exec n8n n8n import:credentials --input=/import/credentials/smtp.json
     docker compose exec n8n n8n import:workflow --separate --input=/import/workflows
     docker compose exec n8n n8n publish:workflow --id=lendloopErrHandler01
     docker compose exec n8n n8n publish:workflow --id=lendloopNotify001
     docker compose exec n8n n8n publish:workflow --id=lendloopReminder01
     docker compose restart n8n
     ```
   - Tell Convex where to send notifications: `npx convex env set N8N_WEBHOOK_URL http://localhost:5678/webhook/lendloop-status`. If Convex runs in the cloud and n8n on your machine, expose n8n with a tunnel and use that URL (and set `WEBHOOK_URL` to it).
6. `npm run dev`, open http://localhost:3000, sign up.
7. Make yourself admin (the browser cannot do this): `npx convex run users:setRoleByEmail '{"email":"you@example.com","role":"admin"}'`
8. Optional demo data (local only, creates two example members, one overdue loan, one open request): `npx convex run seed:demo`

The exported workflows are in `n8n/workflows/` (generated by `scripts/gen-workflows.py`). To see the reminder run immediately,
open "LendLoop - Daily overdue reminders" in n8n and press **Execute workflow** (the manual trigger).

## Architecture

```
Browser ── Clerk JWT ──> Convex (queries, mutations: authz in every function)
                           │  mutation writes loan + automationEvents row, schedules an action
                           ▼
                    Convex action ── HMAC-signed POST ──> n8n webhook ──> SMTP
                           ▲                                   │
   signed GET /n8n/overdue-loans, POST /n8n/reminder-result, /n8n/failure
                           └──────────── n8n daily job / error workflow
```

* `convex/schema.ts`: users, tools, loans, automationEvents.
* `convex/lib/access.ts`: `requireUser`, `requireAdmin`. Every query and mutation starts with one of these (except the deliberately public `tools.listPublic`).
* `convex/loans.ts`: state machine `requested → approved | declined | cancelled`, `approved → returned`. Only the tool's owner decides or marks returned; only the borrower withdraws.
* `convex/notifications.ts`: builds the minimal payload, signs it, delivers with retries (30 s, 2 min, 10 min, 1 h, then `failed`).
* `convex/http.ts`: the three HTTP endpoints n8n calls. Each verifies the HMAC before doing anything.
* `convex/automation.ts`: overdue query and idempotent write-backs.

## Security decisions

* **Authorisation lives in Convex, not the UI.** The UI hides buttons, but every function re-checks identity and ownership. Roles are read from the database row; the client can never send a role. `npm test` runs 24 tests, including "a user cannot edit or delete another user's tool", "an admin cannot answer a loan request on someone else's tool", "signed-out calls are rejected".
* **Identity comes from the verified Clerk token** (`tokenIdentifier`), never from a client-supplied user id.
* **n8n webhooks are signed.** Convex sends `x-lendloop-timestamp` and `x-lendloop-signature` (HMAC-SHA256 over `timestamp.body`). n8n rejects missing, wrong or older-than-5-minutes signatures with 401 and does nothing. Calls from n8n to Convex sign `timestamp.METHOD.path.body`, so a signature for one endpoint cannot be replayed on another. Comparison is constant-time. Bodies over 8 KB are refused.
* **The shared secret is never in the repo or the exported workflows.** It is an environment variable in Convex and n8n (`$env.N8N_SHARED_SECRET`).
* **Idempotency.** Every automation side effect has a unique key (`status:<loan>:<event>`, `reminder:<loan>:<date>`, `failure:<execution>`). Enqueueing twice, retrying a delivery, or posting the same reminder result twice never creates a second record, and a "sent" event is never re-sent. n8n also remembers delivered event ids so a Convex retry cannot cause a second email.
* **Failures are visible.** Delivery failures are retried then marked `failed`; any n8n workflow failure is posted by the error workflow; the admin tab lists both.
* **Input validation** on every mutation (length limits, date format, no past dates, 30-day maximum, no overlapping approved loans, no borrowing your own tool).

## Privacy decisions

* **Data minimisation on the public page:** name, category, availability. No description, condition, owner or ids that point to a person.
* **Members see tools, not owners.** The browse view shows a Trusted Lender badge but not who owns the tool. A lender sees the borrower's name on requests for their own tools; a borrower never sees the lender's identity; other members see neither. Only an admin sees both sides.
* **Notifications carry only what one recipient needs:** the tool name, the dates, and the recipient's own name and email. The lender's "new request" email does not include the borrower's identity, and vice versa.
* **Email addresses stay in Convex and the single email n8n is sending.** They are not exposed to the browser or the public list.
* **Soft deletion:** removed listings are hidden but loan history is kept, so an owner deleting a tool does not erase the other party's record.

## Production changes (what I would do before real use)

1. Use a transactional email provider (Postmark, SES) with SPF/DKIM instead of Mailpit, and add unsubscribe/notification preferences.
2. Run n8n behind HTTPS with Postgres, queue mode and backups; stop using the local compose `latest` tag and pin a version. Put the webhook behind an allow-list or a reverse proxy and rotate `N8N_SHARED_SECRET` on a schedule (support two secrets during rotation).
3. Verify webhook signatures on the raw body rather than a re-serialised JSON object.
4. Use Clerk's webhook (or `identity` claims) to sync user deletion, and add an account-deletion/erase flow for GDPR (anonymise loans, remove email).
5. Rate-limit loan requests and tool creation per user; add pagination (lists are capped at 200 and 500 rows today).
6. Add reputation inputs for the Trusted Lender badge (completed loans, on-time returns) instead of a manual flag, and an admin audit log.
7. Add end-to-end tests with real Clerk test users, monitoring and alerting on `failed` automation events, and per-environment Convex deployments.
8. Dates are plain UTC calendar days. Real use needs the neighbourhood's time zone.
9. Upload tool photos with signed URLs and virus scanning.
